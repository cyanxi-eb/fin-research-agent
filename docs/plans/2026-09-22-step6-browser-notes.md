## ⑤ HITL 挂起与确认（**首轮 FAIL → 修复 → 复测 PASS**）

服务以 `FA_HITL_FORCE_REASON=low_confidence` 启动。

### 首轮（失败）

- 挂起面板**正常出现**：标题「人工确认 · 这是待确认，不是错误」；触发原因 `low_confidence`；引用校验行；候选答案；按钮「确认放行」「驳回」。
- 点「确认放行」→ **失败**，页面提示：

  > 该会话当前没有挂起的流程（409）：thread_id='fa-9506915c16c9' 没有处于挂起状态的流程，无法恢复

### 根因（控制者定位）

流式链路是**手工跑节点**的（不走 `graph.invoke`），定稿时用
`builder.persist_session`（`as_node="finalize"`）落库 —— 那写的是**已完成**态（`next` 为空）。
挂起时也走了这条，于是库里没有挂起点，`resume_agent` 见到空 `next` 直接抛
`ValueError` → HTTP 409。即：**前端面板的 `pending` 来自响应，落库的却是"已完成"**，两者不同形。

探针实证（修复前）：`FOUND True PENDING False NEXT []` —— 与响应 `hitl.pending=True` 矛盾。

交叉核对：**一次性路径**（`run_agent`）对同一问题也挂起（`citation_unsupported`），
说明流式这条路原先与一次性路径**漂移**了，而此前有一条用例断言 `pending is False`，
正是靠这个缺陷才成立。

### 修复

- 新增 `builder.persist_pending`：落 **`verify` 之后、`finalize` 之前**的态
  （`as_node="verify"` → 条件边选出 `hitl` → `next=("hitl",)`），随后 `invoke(None, ...)`
  真正执行 `hitl_node`，由 `interrupt()` 把挂起点落盘。
  存 `verify` 态而非 `finalize` 态，是因为 `finalize_node` 会补免责声明 / 追加 dangling 备注 /
  给 reject 加前缀，**都不幂等**，恢复后会重复追加。
- `streaming._finalize` 按 `hitl.pending` 分流；`_run_subgraph` / `_rag_state` 额外返回
  `verify` 后的状态快照。
- 回归用例：`tests/test_streaming.py::test_pending_persists_resumable_checkpoint`
  （断言 `next == ["hitl"]`、payload 可读、真能 resume）、
  `::test_pending_reject_prefix_applied_once`；并把 `tests/test_history.py` 里那条
  被缺陷喂饱的断言改为「落库态必须与 `done` 响应同口径」。

### 复测（通过）

- 挂起面板出现，对话区文本可读到：「待人工确认（low_confidence）」「人工确认 · 这是待确认，不是错误」
  「触发原因：low_confidence」「引用校验：核对 true · 有出处 true · 无出处数字」
  「已落盘的候选答案（放行后作为对外结论…）」、按钮「确认放行 / 驳回」。
- 点「确认放行」→ **无 409、无其它错误提示**；挂起面板消失；底部状态条新增
  「人工确认： approve」；回答与引用校验保留。
- 控制者另在真实服务上用**与前端相同的请求体**做了 HTTP 端到端复验：
  `POST /api/ask/stream` → `hitl.pending=true` → `GET /api/hitl/{tid}`（`pending=true, next=['hitl']`）
  → `POST /api/hitl/{tid}/confirm` 返回 **200**，`pending=false, reviewed=true`，
  备注落入 notes（`人工确认：approve；备注：HTTP 端到端复验`）。

## 存疑 / 未决

- 「回源核对」在当前数据下**恒为置灰**：`/api/citations` 不返回 `pdf_url` / `adjunct_url`。
  这是 B3 原文规定的兜底路径，但按钮实际上"从来点不亮" —— 若要真正可回源，
  需要在后端把 `reports.url`（巨潮 adjunct url）带进 citation，属**新增范围**，本轮未做。
- B6 原文把「② 引用卡片」与「① 数值题」绑在同一条提问上，而数值题走结构化库、不产生引用；
  实测中已拆开用文档类问题补测。这属**计划文本的口径问题**，实现本身无缺陷。
- 首轮 ⑤ 复测时浏览器侧曾报"未出现面板"，与后端同一时刻的探针结果相反；
  要求读 DOM 文本后复测确认面板确实存在。判断为**首次观察失真**（面板插在气泡底部，未滚动到）。
- `rerank` 通道为黄标（`RERANK_BACKEND=passthrough`），属设计内降级。

## ⑥ 批次 B 复查发现的两条 SHOULD 与修复复测

批次 B 的只读复查（`BLOCK 无`；`344 passed`）提出 2 条 SHOULD，均在本节修复。

### SHOULD-1 · `persist_pending` 写失败时无任何留痕

- 现象：`src/graph/builder.py` 的 `except Exception: return None` 只吞异常、不记录。
- 为什么必须修：写挂起点失败时**前端照样会弹确认面板**，人点下去必然 409 ——
  症状与本节 ⑤ 刚修好的缺陷**完全一样**，但没有任何日志能把两种成因分开。
- 修复：失败分支落一条审计 `audit_mod.log("hitl_persist_failed", ...)`（带 `thread_id` 与异常原文），
  并把 `hitl_persist_failed` 登记进 `src/audit.py` 的 `_ACTIONS`（否则会被打上 `_unknown_action` 标记）。
- 复测：`_ACTIONS` 含该动作；`pytest -q` 仍 `344 passed`。

### SHOULD-2 · 趋势图纵轴刻度溢出被裁（用户可见）

- 现象（修复前）：纵轴刻度直接印原始值（`172,054,171,890.91`，18 字符 ≈ 100px+ 宽），
  而刻度锚在 `padL - 8 = 70`、`text-anchor="end"`，根 svg 默认 `overflow:hidden`
  → 文字左边缘跑到视口外，**默认指标（营业总收入）下纵轴不可读**。
- 修复：① 新增 `axisScale()`，按量级缩放到 亿/万 再印刻度（`1,741.44亿`），
  并在图下加一行说明「纵轴刻度按「亿」缩放（刻度值 × 100,000,000 = 原始数值）」；表格仍印原始值；
  ② `padL` 78 → 118，给刻度文字留足余量（不赌字体度量）。
- 顺带修掉同一函数里的一个既有缺陷：`renderCompare` 先 `chartBox.appendChild(h4)` 再调
  `renderChart`，而后者首行是 `container.innerHTML = ""` —— **图表标题被清掉、一直不可见**。
  改为 `renderChart` 之后再 `insertBefore(h4, firstChild)`。
- 复测（硬刷新 `/?v=2` 后读 DOM 原始值）：
  - 纵轴 5 个刻度文本 = `405.29亿` / `739.32亿` / `1,073.36亿` / `1,407.40亿` / `1,741.44亿`；
  - 刻度锚点 `x=110`，`getBBox().x` = `66.16 / 66.96 / 58.65 / 58.65 / 58.65` —— **全部 ≥ 0**，不再裁切；
  - `.cmp-chart` 文本含缩放说明。
- 复测前的**一次观察失真**（已排除）：首轮测量报 `bboxX ≈ -16.6 ~ -22.6` 且「说明文字不存在」，
  但同一轮又读到刻度已是 `X,XXX.XX亿` 新格式 —— 两项自相矛盾（说明文字与刻度后缀由同一函数追加）。
  换 URL 硬刷新 + 只采原始 JSON 后，结果自洽（宽度 ≈ 44~51px，与 `.axis` 的 11px 字号相符）。
  故判定为**首次观察失真**，非代码缺陷。
